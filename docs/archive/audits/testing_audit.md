# Аудит тестирования «Азимута» — этап I

27 октября 2026 года, версия 0.64.7, коммит `1774c34`. По заданию автора («Техническое задание: аудит и совершенствование системы тестирования»), только этап I. Полное покрытие (этап II) — после прогона на macOS или в CI. В программе и тестах ничего не менялось.

## Как проверялось

- **Окружение:** Linux aarch64, CPython 3.13.17, numpy 2.5.3, pytest 9.1.1, без PySide6 и VTK. Их нельзя было установить: PyPI в этом окружении закрыт. Поэтому тесты интерфейса и 3D здесь не запускались. Их данные ниже получены разбором исходного кода, а не прогоном. Каждое такое место помечено.
- **Инструменты вне проекта**, без новых зависимостей:
  - разбор синтаксического дерева всех `tests/test_*.py` — количество тестов, параметризация, вид каждой проверки `assert`;
  - собственный подсчёт покрытия строк через `sys.monitoring` (Python 3.12+) в виде модуля pytest;
  - выборочное чтение тестов и модулей.

  Скрипты не входят в репозиторий.
- **Ограничения:**
  - покрытие ветвей не измерялось;
  - для кода, который импортирует PySide6 или VTK, покрытие не измерено вовсе;
  - классификация проверок автоматическая: она показывает общую картину, но не оценивает каждый тест.

## 3. «Самодельный запускатель тестов»

В репозитории его нет. Тесты запускаются обычным `pytest`:
- `pytest.ini` содержит только `pythonpath` и `testpaths`;
- в `tools/` лежат только сборка библиотеки молекул и три проверки окна VTK;
- `verify_install.py` — проверка установки (Python, зависимости, хеши ресурсов, построение поверхности), а не тестов.

CI (`.github/workflows/tests.yml`) запускает `python -m pytest -q` на `macos-latest` и `windows-latest` с `QT_QPA_PLATFORM=offscreen`. Linux в матрице нет, покрытие там не измеряется. Если в задании имелся в виду способ, которым тесты гонял кто-то из прежних помощников, по репозиторию его не восстановить.

## 4. Что проверяют тесты

Каждую проверку `assert` я разложил на простые условия: `a and b` даёт два условия, `all(...)` — условие внутри. Получилось 3431 элементарное условие:

| Вид проверки | Число | Комментарий |
|---|---|---|
| Точный текст (`== 'строка'`) | 627 | Входные файлы, имена, сообщения |
| Равенство (числа, кортежи, структуры) | 553 | |
| Число с допуском (`approx`, `isclose`, `abs(...) <`) | 452 | |
| Отрицание (`not ...`) | 282 | Чаще всего «не выдумано», «не включено» |
| Вызов, вернувший истину | 321 | Например, `np.array_equal`, `is_file` |
| Принадлежность (`in`) | 295 | |
| Неравенство (`<`, `>`) | 226 | Границы, монотонность |
| `is None` / `is` | 205 | Отказ на испорченных данных |
| Длина (`len(...) ==`) | 195 | |
| Точное равенство вещественных чисел | 137 | Числа, переписанные из файла с той же точностью печати |
| Прочее (истинность, тип, существование файла) | 138 | |

- **Тесты без единой проверки** — 3 функции. Все три проверяют через вспомогательную функцию или через исключение: `test_core.py::test_doublet_ion`, две функции в `test_vibration_contract.py`. Ложных среди них нет.
- **Тесты без единого «сильного» условия** — 52 из 615 функций (8%). Сильным я считаю число с допуском, точное значение, равенство или неравенство. Почти все 52 намеренно проверяют отказ: «на испорченный файл — `None`, а не догадка» (`test_vibrations.py`, `test_trajectory.py`, `test_orca_properties.py`), «IUPAC не называет вне правил», «VPN не отвечает». Это осмысленные проверки. Шесть тестов в `test_gui.py` проверяют только состояние кнопок и окон, для интерфейса это нормально.
- **Допуски.** Широкие допуски встречаются, и все обоснованы в тексте теста. Например, 2–3° для геометрии начального построения, где оптимизации нет. Или «20 единиц последнего знака» для суммы округлённых напечатанных чисел.
- **Случайность** везде с фиксированным зерном (9 файлов). Сеть отключена: PubChem вызывается с подставным `urlopen`. Внешние программы подменяются: ORCA и xtb — поддельной программой, conda — поддельным `conda` в `PATH`.

## 8. От чего зависят тесты

- **PySide6 и VTK** — см. п. 2.
- **Сеть** — нигде. PubChem вызывается с подставным `urlopen`, проверены и ответ, и «нет сети».
- **Внешние программы** — нигде по-настоящему. ORCA, xtb и conda подменяются поддельными программами во временном `PATH`. VPN (OpenVPN Connect) и сервер проверяются с подставными вызовами.
- **Операционная система:** значок Dock, Связка ключей и OpenVPN Connect есть только на macOS. Тесты значка отключают его в тестовом режиме. Тестов Связки ключей нет.
- **Отображение:** Qt в режиме `offscreen`. В `conftest.py` есть защита: любое модальное окно, которое не подменили в тесте, валит тест, а не вешает прогон. По заданию, проверка без окна не заменяет визуальную.
