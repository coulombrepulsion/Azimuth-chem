# Азимут без окна: команды и MCP-сервер

`azimuth/headless.py` — команды Азимута без окна: молекула, настройки расчёта, входной файл, запуск на этом
компьютере, состояние, результат, совет доктора; а также запуск проверок программы (`tools/test.py`). Это тот же
код, что у Секстанта и Спектра: входной файл тот же, расчёт ложится в ту же папку расчётов.

`tools/azimuth_mcp.py` — MCP-сервер поверх этих команд. Через него языковая модель (Claude или локальная — через
любой MCP-клиент) готовит и запускает расчёты, читает результаты и запускает тесты программы.

## Инструменты сервера

| Инструмент | Что делает |
|---|---|
| `azimuth_programs` | какие расчётные программы найдены на этом компьютере |
| `azimuth_options` | задачи, методы, базисы, растворители, дисперсия программы |
| `azimuth_preview_input` | входной файл для молекулы и настроек — ничего не запускает |
| `azimuth_run` | запустить расчёт на этом компьютере → номер задания |
| `azimuth_crystal_options` | задачи и настройки расчёта кристалла в Quantum ESPRESSO (`qe`) или CP2K (`cp2k`) с их значениями по умолчанию |
| `azimuth_crystal_preview` | входные файлы для кристалла (CIF текстом или файлом) и настроек — ничего не запускает |
| `azimuth_crystal_run` | запустить расчёт кристалла на этом компьютере → номер задания; ход и остановка — `azimuth_status`, `azimuth_stop`, результат — `azimuth_result` по папке расчёта |
| `azimuth_status` | ход задания; у законченного расчёта — его результат |
| `azimuth_stop` | остановить задание |
| `azimuth_jobs` | задания этого сервера |
| `azimuth_result` | прочитать вывод или папку расчёта: энергия, сходимость, частоты, термохимия, возбуждения, ошибки и совет доктора |
| `azimuth_server` | что сейчас говорит сервер SLURM из профиля Секстанта: свободные ядра и память, сколько может взять один расчёт, найдены ли ORCA и MOPAC, какие отправленные отсюда расчёты ещё открыты |
| `azimuth_run_server` | отправить один расчёт ORCA или MOPAC на сервер (sbatch) → номер задания; дальше — `azimuth_status`, `azimuth_stop` |
| `azimuth_server_resume` | снова следить за расчётом, отправленным до перезапуска сервера управления (ничего не отправляется повторно) |
| `azimuth_tests` | `tools/test.py affected / quick / area <имя> / full / isolated / list` → номер задания (`full` — частями в нескольких процессах) |

Молекула задаётся как `{"smiles": "CC=O"}`, `{"xyz": "<текст XYZ>"}` или `{"path": "<файл структуры>"}`.
Настройки — поля расчёта Секстанта: `{"method": "B3LYP", "basis": "def2-SVP", "task": "Оптимизация + частоты",
"cores": 4, "solvent": "water"}`.

Чего сервер не делает: ничего не удаляет, не делает git push, не выполняет произвольных команд — ни здесь, ни на
сервере SLURM. Опции pytest для тестов — только из безопасного списка (`headless.SAFE_OPTIONS`).

## Расчёт на сервере SLURM (0.222.15)

Решение владельца 2026-11-22: модель может ставить расчёты на сервер из профиля «Сервер для расчётов» Секстанта.
Сервер общий, поэтому ограничения записаны в коде (`azimuth/headless_server.py`), а не оставлены на аккуратность
того, кто вызывает:

| Правило | Как сделано |
|---|---|
| Вход только по SSH-ключу | `ssh` с `BatchMode=yes`: пароль не спрашивается, не читается из связки ключей и не передаётся. Если сервер хочет пароль — отказ с подсказкой: «Вход без пароля» в окне «Сервер для расчётов» один раз кладёт ключ программы на сервер |
| VPN — только профиль, выбранный владельцем | сервер не отвечает, а в его профиле в карточке «VPN» выбран профиль OpenVPN Connect — программа просит OpenVPN Connect подключить именно его (как это делает окно), ждёт до минуты и спрашивает сервер ещё раз (0.222.17). Профиль не выбран — так и сказано, ничего не включается. Окно OpenVPN Connect на macOS скрывается; не подключился за 15 с — открывается (возможно, он ждёт пароль). VPN отсюда никогда не выключается |
| Только ORCA и MOPAC | то, что сервер умеет считать (`remote_job.REMOTE_KINDS`) и что на нём найдено |
| Ядра | Сервер со SLURM — очередь (0.242.0): ядер столько, сколько запрошено (8, если не задано), не больше 80 % ядер узла на одну задачу; свободных меньше — `sbatch` принимает задачу, и она ждёт. Сервер без SLURM: не больше свободных сейчас и так, чтобы вместе с уже занятыми было занято не больше 80 % ядер узла; взять нечего — отказ. Запрошено больше потолка — отказ с числом, без молчаливого урезания. |
| Память | 2000 МБ на процесс, если не задано; запрос задания (процессы × память × 1,25): на сервере со SLURM — не больше 80 % памяти узла, без SLURM — не больше половины свободной памяти сервера |
| Предел времени всегда записан | `-t` профиля, иначе 4 часа (можно просить до 24) |
| Не больше трёх расчётов сразу — только без SLURM | считаются расчёты журнала, отправленные на этот сервер, про которые не известно, что они закончились; у очереди SLURM такого предела нет |
| Журнал | каждая отправка и её конец — строка в `azimuth_server_journal.jsonl` в папке расчётов: время, сервер, папка, программа, ядра, память, предел времени |
| Сервер без SLURM | расчёт запускается сразу через `nohup` (номер задания — номер процесса, предел времени держит `timeout`), и только если ядра свободны: занятые считаются по средней загрузке сервера, ядра расчётов, отправленных в последние пять минут, вычитаются |
| Останавливается только своё | `azimuth_stop` — это `scancel` номера своего задания (без SLURM — завершение своего процесса); продолжить слежение можно только за расчётом из журнала |

Расчёт готовится тем же кодом, что в окне (`remote_job.prepare_remote`, `cluster.job_script`), ложится в ту же папку
расчётов, и результаты скачиваются туда же. Число процессов и память из настроек расчёта заменяются теми, что
выбраны для сервера. В окне программы такой расчёт не появляется сам: его папку можно открыть как любой результат.

## Подключить к приложению Claude (macOS)

1. Открыть файл `~/Library/Application Support/Claude/claude_desktop_config.json` (если его нет — создать) и добавить:

```json
{
  "mcpServers": {
    "azimuth": {
      "command": "/Users/me/Projects/Azimuth-программа/.venv/bin/python",
      "args": ["/Users/me/Projects/Azimuth-программа/tools/azimuth_mcp.py"]
    }
  }
}
```

   Если в файле уже есть `mcpServers`, добавить в него только блок `"azimuth": {…}`.
2. Перезапустить приложение Claude. В настройках, в разделе разработчика или коннекторов, появится сервер
   «azimuth»; его инструменты видны в разговорах, связанных с этим компьютером.

Проверить сервер без клиента:

```
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | .venv/bin/python tools/azimuth_mcp.py
```

## Подключить к локальной модели

Сервер говорит по стандартному протоколу MCP через stdin/stdout, поэтому подходит любой клиент с поддержкой MCP
(например, LM Studio или клиенты для Ollama): в его настройках указывается та же команда и те же аргументы.
Модели нужна поддержка вызова инструментов (tool calling).

## Из своего скрипта

```python
from azimuth import headless

print(headless.preview('orca', {'smiles': 'CC=O'}, {'task': 'Оптимизация + частоты'}))
jobs = headless.Jobs()
job = jobs.start_calculation('xtb', {'smiles': 'CC=O'}, {'task': 'Оптимизация'})
print(jobs.status(job['job']))          # повторять, пока state не станет 'done' или 'failed'
print(headless.result(job['folder']))
```
