# Проигрывание оптимизации
## §1 Назначение
Последовательный показ напечатанных циклов ORCA. Это не молекулярная динамика:
скорость показа не соответствует физическому времени.
## §2 Алгоритм
Один QTimer timeout выбирает следующий индекс таблицы. После последнего шага
таймер выключается. Play на последнем шаге начинает с первого; Pause сохраняет
позицию; Stop возвращает к первому. Ручной выбор шага ставит показ на паузу.
## §3 Интерфейс
Спектр → Оптимизация. Иконки Play/Pause и Stop; скорость 0.2…20 шаг/с.
Таблица, график энергии, модель и действие переноса в Компас обновляются вместе.
## §4 Контракт
Шаги не пропускаются и не интерполируются. При отсутствии координат отображается
пустая модель с сообщением. При 0/1 шагах Play отключён. Новый файл, скрытие
вкладки или окна останавливают таймер. Заданный интервал round(1000/скорость) мс.
## §5 Реализация
modules/spectrum/views/trajectory.py: set_playing, advance, reset_playback, hideEvent.
## §6 Ограничения
Qt может задерживать кадры при нагрузке; скорость целевая, не гарантированная.
Камера сохраняется между шагами; кнопка центрирования остаётся доступной.
## §7 Проверки
Независимые сценарии состояний на трёх шагах: пауза, конец, повторный старт,
сброс, пустой/одиночный набор, ручное выделение, скрытие, смена скорости.
Реальный журнал с 56 циклами проверяется в настоящем окне macOS.
## §8 Устойчивость
Обратная связь таблицы не останавливает автоматический переход: флаг _advancing
действует только внутри одного тика с восстановлением в finally. На паузе
запоздалый вызов advance не меняет шаг. Изменения численных алгоритмов нет.
