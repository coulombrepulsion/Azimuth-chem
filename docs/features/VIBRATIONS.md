# Нормализация колебаний

## §1 Теория
Для каждого атома задан декартов вектор v_i. Нормировка u_i=v_i/max_j||v_j||₂
сохраняет относительные смещения. Это иллюстрация движения, не динамика молекулы.

## §2 Алгоритм
Проверить конечность частоты и всех компонент, размер каждой строки 3.
При нулевой частоте, отсутствии векторов или всех нулевых компонентах вернуть ().
Иначе s=max|v_ik|, w=v/s, m=max hypot(w_i), u=w/m. Масштабирование защищает
от переполнения квадратов и исчезновения малых ненулевых векторов.

## §3 Применения
Анимация положительных и отрицательных (мнимых) частот; максимальное
смещение задаётся отдельно в ангстремах. Нулевая частота не анимируется.

## §4 Спецификация
Vibration(index:int, frequency:float, vectors:tuple[tuple[float,float,float],...]|None,
intensity:float|None). Частота конечная, в см⁻¹; интенсивность в км/моль
не участвует в нормировке. normalized_vectors(mode) возвращает tuple строк из
трёх безразмерных float, исходный объект не изменяет. Неверная размерность,
NaN и бесконечность вызывают ValueError. Все конечные ненулевые масштабы допустимы.

## §5 Процедуры
Реализация: modules/spectrum/readers/vibration_data.py, _validate_mode и normalized_vectors.
Парсер ORCA в этом модуле имеет отдельные правила и не покрывается данным контрактом.

## §6 Реализация
O(N) времени и памяти. Два деления после масштабирования, hypot вместо суммы
квадратов. Ненулевая компонента может округлиться в ноль при экстремальном
отношении масштабов. Побитовая эквивалентность старой реализации не заявляется:
исправлены переполнение и порог, скрывавший малые векторы.

## §7 Независимые примеры
(3,4,0) → (0.6,0.8,0); (1e308,0,0) → (1,0,0);
(1e-320,0,0) → (1,0,0). Оракулы — треугольник 3–4–5 и осевой единичный вектор.
Тесты test_vibration_contract.py написаны отдельным агентом только по §1–§4,
без доступа к реализации и прежним тестам.

## §8 Погрешность
Для нормальных результатов масштабирование и финальное деление вносят по
одному округлению, hypot — до нескольких ulp. Для короткого вектора контроль
абсолютной ошибки 32*epsilon оставляет запас на три компоненты, сравнение двух результатов и вычисление
нормы проверяющим кодом. Это абсолютная граница для нормированных компонент,
не относительная гарантия для исчезающе малых компонент. Для осевых случаев
результат 1 представим точно. Изменение порядка операций исключает bitwise-гарантию.

Дополнительный эталон: Decimal с точностью 100 значащих цифр, входы переведены
через Decimal.from_float, чтобы сравнивать одни и те же двоичные числа.
Уровень проверки — bound(32*epsilon), не bitwise. Отчёт
docs/archive/audits/normalization-verification.txt: 4/4 семейства, максимальная абсолютная разница
1.11e-16, максимальная доля границы 0.0156; вход не меняется, порядок хранения
и повторный вызов не меняют результат.
