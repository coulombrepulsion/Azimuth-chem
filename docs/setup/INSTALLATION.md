# Установка и диагностика

## §1 Задача
Восстановить проверяемое окружение приложения, не меняя системный Python.
Контрольные суммы фиксируют содержимое колёс, но не гарантируют одинаковый
рендеринг на разных видеокартах.

## §2 Алгоритм
Шесть шагов: проверить Python; создать или использовать окружение; выбрать
платформенный lock; установить зависимости с SHA256; использовать комплектные
учебные файлы; выполнить диагностику и сохранить фактический pip freeze.
Ошибка любого обязательного шага останавливает установку с ненулевым кодом.

## §3 Применения
Новая установка, проверка существующего окружения, автономная установка из
каталога колёс. Графическое приложение установщик не запускает.

## §4 Параметры
setup.sh: --python PATH (по умолчанию python3), --skip-venv (явно использовать
выбранный интерпретатор), --debug (трассировка), --no-download (запрет сети),
--offline-bundle DIRECTORY (каталог колёс: создать при сетевой установке,
читать при --no-download). setup.ps1: соответствующие PythonBin, SkipVenv,
Debug, NoDownload, OfflineBundle; PythonBin принимает путь; по умолчанию (`auto`, 0.91.58) — первый 64-разрядный Python 3.12 или 3.13 из `py -3.13`, `py -3.12`, `python`, `python3`; не 3.13 — библиотеки из requirements.txt (те же версии, без хешей).
Цели lock: Python 3.13, macOS arm64 и Windows x64. Это проверенные цели
зависимостей, не заявление о несовместимости всех остальных версий Python.
Существующая .venv не удаляется. Установка изменяет выбранное окружение.
verify_install.py [--quick]: вывод ASCII, код 0 только при успехе всех проверок;
quick пропускает построение VTK-поверхности. Запускается из любого каталога.

## §5 Процедуры
setup.sh, setup.ps1, windows_first_run.bat, verify_install.py.

## §6 Реализация
Особых GPU/CUDA зависимостей и загружаемых моделей нет. Окружение Conda требует
явного подтверждения. assets-manifest.json фиксирует примеры и HTML-руководство;
это контроль целостности комплекта, не подпись издателя. Колёса хранятся каталогом,
архив не создаётся: для переноса скопировать его вместе с исходниками и lock.

## §7 Проверки
Оракулы: метаданные реально скачанных PyPI-колёс, SHA256 файлов комплекта,
построение непустой поверхности VTK. Результаты и ограничения — AUDIT.md.

## §8′ Устойчивость
Сеть не нужна при --no-download; недостающее колесо вызывает ошибку pip.
Частично установленное окружение не объявляется готовым. Проверка импорта не
доказывает работоспособность графического драйвера: требуется настоящий запуск.

## Первый запуск: «неизвестный разработчик» (2026-11-16)

Программа не подписана платными сертификатами Apple (Developer ID и нотаризация) и Microsoft (подпись кода):
владелец решил пока их не покупать. Поэтому файлы из архива, скачанного браузером или полученного письмом,
система помечает как «из интернета» и при первом запуске предупреждает, что не может проверить разработчика. С
программой всё в порядке — запуск нужно один раз разрешить. Папка, полученная через `git clone`, такой пометки не
получает, и предупреждений нет.

**macOS.**

1. Один раз для всей папки (быстрее всего): в Терминале набрать `xattr -dr com.apple.quarantine `, затем
   перетащить в окно Терминала распакованную папку программы (появится её путь) и нажать Return. Снимается пометка
   «из интернета» со всех файлов — с `Azimuth.app`, `Launch-macOS.command` и остальных.
2. Без Терминала: попытаться открыть `Azimuth.app`, в окне предупреждения нажать «Готово»; открыть «Системные
   настройки → Конфиденциальность и безопасность», внизу у строки об «Azimuth» нажать «Всё равно открыть» и
   подтвердить паролем. В macOS 15 (Sequoia) и новее правый щелчок → «Открыть» проверку больше не обходит — нужен
   именно этот путь. Если понадобится `Launch-macOS.command`, с ним то же самое.
3. Готовая сборка из образа диска (packaging/README.md, без подписи): то же для приложения в «Программах» —
   `xattr -dr com.apple.quarantine /Applications/Azimuth.app` или «Всё равно открыть».

**Windows.**

1. До распаковки: правый щелчок по архиву → «Свойства» → внизу флажок «Разблокировать» → «ОК» (или в PowerShell
   `Unblock-File .\Azimuth.zip`). Тогда файлы внутри не получат отметку «из интернета».
2. Если всё же появилось синее окно «Система Windows защитила ваш компьютер» (SmartScreen): «Подробнее» →
   «Выполнить в любом случае». Так же — для установщика готовой сборки.
3. Антивирус иногда принимает неподписанные сборки PyInstaller за подозрительные; файлы программы можно проверить
   по контрольным суммам `assets-manifest.json` или поставить из исходников (`windows_first_run.bat`).

**Linux.** Подпись не нужна. Если после распаковки скрипт не запускается («Permission denied»), вернуть ему право на
запуск: `chmod +x Launch-Linux.sh setup.sh`.

Бесплатная подпись для Windows возможна через SignPath Foundation, но только для программ с открытой лицензией,
одобренной OSI (signpath.org/terms); для macOS бесплатной нотаризации нет.

## Linux (0.194.0)

Цель — Linux x86_64 с glibc 2.34 и новее (PySide6 6.12 собран как manylinux_2_34): Ubuntu 22.04+, Debian 12+,
Fedora 35+, Linux Mint 21+. Проверено автоматически (тесты без окна и без VTK); окно на живом рабочем столе — по
отчётам. ARM (aarch64) и glibc старше 2.34 не поддерживаются.

1. Python 3.13 (подходит и 3.12) с модулем venv. Ubuntu 24.04: `sudo apt install python3 python3-venv`
   (3.12); Ubuntu 22.04 — Python 3.12 или 3.13 из deadsnakes (`python3.13 python3.13-venv`). Fedora:
   `sudo dnf install python3.13`.
2. Системные библиотеки Qt, которых нет в минимальной установке: Ubuntu/Debian —
   `sudo apt install libxcb-cursor0 libegl1 libxkbcommon-x11-0`; Fedora — `sudo dnf install xcb-util-cursor`.
3. Распаковать папку программы и в терминале выполнить `./Launch-Linux.sh`: первый запуск — `setup.sh`
   (зависимости по `requirements-lock-linux-x86_64.txt` с SHA256 для Python 3.13; для 3.12 — `requirements.txt`),
   затем окно программы.
4. В меню приложений: `./Launch-Linux.sh --install-desktop` — ярлык `~/.local/share/applications/azimuth.desktop`,
   значки, обработчик ссылок `azimuth://` сайта («Открыть в Компасе»). Убрать — `--remove-desktop`. После переноса
   папки программы выполнить `--install-desktop` ещё раз: в ярлыке записан её путь.

Wayland: Qt выбирает его сам; если окно или модель рисуются неправильно, запустить под X11:
`QT_QPA_PLATFORM=xcb ./Launch-Linux.sh`.

## Программы для расчёта (0.44.0)

ORCA на нескольких процессах нужен Open MPI 4.1 (сборки ORCA для macOS и Linux связаны с `libmpi.40`). Секстант ставит
его, а также xtb и CREST, с conda-forge в `.tools/calc` внутри папки программы: кнопка «Установить Open MPI…» в карточке
«Запуск расчёта» или «Расчёт → Установить программы для расчёта…»; то же из терминала:
`.venv/bin/python -m modules.sextant.install_tools [openmpi] [xtb] [crest]`. Используется conda, mamba или micromamba
компьютера, иначе micromamba скачивается с micro.mamba.pm в `.tools/bin`. Лог — `.tools/install.log`. Папка `.tools`
не входит в репозиторий; удалить — значит удалить установленное. Windows: ORCA нужен MS-MPI (установщик Microsoft).
