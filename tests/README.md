# Тесты Азимута

Запуск всех: `.venv/bin/python -m pytest tests -q -p no:cacheprovider` (Windows: `.venv\Scripts\python`).

## Уровни проверки (2026-11-12, `TEST_FEEDBACK_PLAN.md`, этапы 1–3)

`tools/test.py` запускает pytest отдельным процессом, показывает ход и оставляет отчёт в `artifacts/tests/<время>-<профиль>/`: `log.txt`, `summary.json` (время сбора и фаз каждого теста, коммит, версии, режим графики) и `junit.xml`.

| Команда | Что запускает | Когда |
|---|---|---|
| `.venv/bin/python tools/test.py quick` | явный список: чтение и запись форматов, входные файлы программ, чтение выводов, хранилище проекта, записи расчётов, переводы, несколько сценариев окна (~180 тестов, ~25 с) | первый сигнал после небольшой правки |
| `… tools/test.py area NAME` | область: `compass`, `crystal`, `sextant`, `server`, `spectrum`, `projects`, `runtime`, `core`, `hub`, `atlas`, `gui` | основная проверка задачи |
| `… tools/test.py affected` | файлы тестов, зависящие от изменённых файлов (по импортам, `tools/test_affected.py`); `--base REF` — от ревизии | после каждой правки |
| `… tools/test.py full` | весь `tests/`, частями в нескольких процессах сразу | перед push (правило владельца), после широких правок, перед выпуском |
| `… tools/test.py isolated` | каждая папка отдельным процессом (то же, что `tools/run_test_groups.py`) | после правок фикстур, настроек, порядка импортов |
| `… tools/test.py profile` | весь набор с `--durations` | до и после оптимизации |
| `… tools/test.py list` | составы профилей и файлы вне областей | при добавлении файла тестов |

`full` и `affected` идут частями: файлы делятся по их времени в последнем полном прогоне (`testkit.plan`), каждая часть — отдельный pytest со своими временными настройками, проектами и журналами; процессов — ядра минус два, не больше 6 (`--jobs N`; `--jobs 1` — один процесс, как раньше). Отчёт частей — `part-N/` в папке прогона, сведённые — рядом, как у одного прогона. Часть короче минуты не выделяется: её запуск стоит дороже выигрыша.

Опции: `--dry-run` — состав и число тестов без запуска; `--timeout МИН` — предел времени (превышение — провал); после `--` — опции pytest (`-- -x -k crystal`). Успех только «ПРОЙДЕН»: пустой набор, прерывание, падение нативной библиотеки и превышение времени — провал (код 1). `quick` и `area` не называют себя полной проверкой: результат печатает, что осталось непроверенным. Состав — `tools/test_profiles.py` (новый файл тестов — в подходящую область). Пока тест длится дольше 15 с, раз в 15 с печатается строка `[тесты идут …]` с его именем и фазой (`AZIMUTH_TEST_HEARTBEAT`, `AZIMUTH_TEST_SLOW`). Плагин замера можно подключить и к обычному pytest: `-p tools.pytest_timing`.

В `tests/gui_support.py` — только фикстуры и помощники: функция `test_*` в нём собиралась бы ещё раз в каждом модуле с `import *` (до 2026-11-12 так 5 сценариев запускались 40 раз; их места — `test_gui_sextant.py` и `test_gui_settings.py`).

## Папки (0.105.18)

- `compass/` — Компас без окна: построение, выравнивание, конформеры, кристаллы, симметрия, названия, форматы, поле модели.
- `sextant/` — Секстант: входные файлы, программы, очереди, сервер, конформеры и комплексы очереди.
- `spectrum/` — Спектр: чтение выводов, спектры, термохимия, орбитали, плотность, Multiwfn.
- `gui/` — окно целиком по разделам (`test_gui_compass`, `…_files`, `…_sextant`, `…_spectrum`, `…_multiwfn`, `…_settings`); общие фикстуры — `gui_support.py`.
- `projects/` — проекты и вкладки-проекты.
- `hub/` — общее окно, меню разделов, реестр.
- `atlas/` — связь с Атласом и его модели.
- `core/` — общее: переводы, настройки, восстановление, установка, значки, задачи в фоне.
- `data/`, `fixtures/` — эталонные выводы программ и записи ответов (у каждой папки — свой README); `conftest.py`, `fake_programs.py`, `fake_server.py` — общие для всех.
